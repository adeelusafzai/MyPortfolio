CarPool

Personal project · 2026 — Present

A full-stack carpooling platform: drivers post rides with seats, route and time; passengers search and request bookings; driver identity is verified before anyone can post, with an admin panel for moderation.

  • React 19
  • Vite
  • Express 5
  • PostgreSQL
  • Prisma
  • Zod
  • JWT
  • Cloudflare R2
Build notes

Challenge

A two-sided marketplace with a trust problem baked in: anyone can claim to be a driver, and a naive booking flow lets two passengers grab the same last seat at once. Three genuinely different permission levels — passenger, driver, admin — risked turning every route into a tangle of if checks.

Approach

Modelled roles as capability checks rather than identity checks, so a driver is a superset of a passenger rather than a sibling role. Driver verification lives in its own state machine, separate from the account role, so an application can be reviewed without granting access early. The booking race is closed with a single conditional update guarded on available seats instead of a read-then-write — a classic TOCTOU bug turned into an atomic compare-and-set. Licences, registrations and car photos are split across public and private object storage, so sensitive ID documents are never served from an open URL.

Result

In active development — auth, ride posting and the role model are in; bookings, driver verification and the admin panel are in progress.

Job Application Automation

Zapply · Oct 2025 — Jul 2026

An LLM-assisted job application tool: reads a job posting and the candidate's profile, then auto-fills application forms with tailored answers, cutting repetitive form-filling out of the job search.

  • TypeScript
  • React
  • Node.js
  • Express
  • PostgreSQL
  • LLM APIs
Build notes

Challenge

Every job posting phrases the same questions differently, and every form has its own field layout — a naive autofill breaks the moment the form deviates from the last one it saw.

Approach

Own the feature end to end: an LLM reads the posting and the candidate's profile to produce tailored answers, which are then mapped onto the target form's actual fields rather than a fixed template — with the client, API and data layer built in TypeScript throughout.

Result

Repetitive form-filling removed from the job search, with answers tailored per posting instead of copy-pasted.

  • PyQt5
  • Tesseract OCR
  • Genetic Algorithm
  • pandas
  • NumPy
Build notes

Challenge

Cricket broadcasts carry no structured event feed — the only reliable signal for "something happened" is the scoreboard burned into the frame.

Approach
